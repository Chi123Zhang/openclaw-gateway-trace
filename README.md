# OpenClaw Gateway Trace Viewer

Interactive source-level trace viewer for the OpenClaw Gateway `chat.send` path.

The project now supports two modes:

1. **Saved trace** — the existing `How to make a cake?` G0–G18 run.
2. **Live trace** — enter a new question in the webpage, send it through a local OpenClaw collector, and render the returned Gateway trace.

## Live site

```text

```

Saved Cake trace:


## Architecture

```text
Browser / GitHub Pages
        │
        │ POST /api/run
        ▼
Local collector :8765
        │
        ├── openclaw gateway call chat.send
        ├── chat.history → assistant response
        └── TraceClaw JSONL → G0–G18 runtime events
                    │
                    ▼
          normalized trace payload
                    │
                    ▼
             existing dashboard
```

The collector runs on the same machine as OpenClaw, so Gateway credentials do not need to be embedded in the public static site.

## Shared Gateway definitions

The shared G0–G18 source structure lives under `data/stages/` and contains:

- stage names and module ownership
- purpose
- generic input/output
- process steps
- source mapping
- source-aligned pseudocode

These definitions remain shared across questions for the same OpenClaw source snapshot.

## Run live questions

See `collector/README.md` for the full setup.

Minimal startup:

```bash
git clone https://github.com/Chi123Zhang/openclaw-gateway-trace.git
cd openclaw-gateway-trace/collector
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Use the JSONL file generated by the existing TraceClaw Gateway instrumentation.
export TRACECLAW_LOG_PATH='/absolute/path/to/gateway-runtime.jsonl'

uvicorn server:app --host 127.0.0.1 --port 8765 --reload
```

Then verify:

```bash
curl http://127.0.0.1:8765/health
```

and test one live request:

```bash
curl -X POST http://127.0.0.1:8765/api/run \
  -H 'Content-Type: application/json' \
  -d '{"message":"How to make pasta?"}'
```

`config.js` currently points the webpage to:

```text
http://127.0.0.1:8765
```

## Evidence policy

The live collector does not invent missing G-stage observations.

- runtime events are marked as runtime evidence;
- shared source structure remains source evidence;
- request-known values may be shown as request/source-derived;
- stages without standalone runtime events remain `not separately observed`.
